## 2. 何を作るか (30 秒で把握する要約)

Linux の sysstat が出力する日次ログをブラウザでグラフ表示するビューア。画面は 2 つだけ。

1. **SC-01**: 期間を指定してログファイルを検索し、一覧 (1ページ10件・ラジオ単一選択) から 1 件選ぶ。
2. **SC-02**: 選んだファイルの全時系列データを、見出しと説明付きのグラフで表示する。戻ると SC-01 が遷移前の状態に復元される。

対象ファイルは 2 種類あり、**読み取り経路が異なるが結果は同一構造に正規化する**。

* `sarDD` (テキスト) → 自前解析
* `saDD` (バイナリ) → `sadf -j` で変換

## 3. 実装前に必ず把握すべき 5 点

### (1) `sar` テキスト解析の落とし穴 — ここを間違えると「それらしいが間違ったグラフ」が出る

* **繰り返されるヘッダ行の直前には必ず空行が入る。**「空行 = セクションの終わり」と実装すると、1 グループの 11 サンプル分しか読めない。同一列構成のブロックは連結すること。
* `Average:` で始まるブロックは期間平均。**時系列サンプルから除外する。**ヘッダ行を伴う点に注意。
* 列は空白揃えで固定幅ではない。`str.split()` を使う。
* 検算: `sar23` の `MG-CPU` の `timestamps` は **144 件前後**になる。11 件や 13 件なら連結できていない。

### (2) 2 経路の結果は一致しなければならない (REQ-F-024)

* 両リーダは共通の中間表現 `RawTable` を返し、**同一の `normalize()` に通す**。
* `sa` 経路のために別の正規化ロジックを書かない。
* 指標名は **`sar` テキストの表記に揃える** (`sadf` の `user` → `%usr`)。対応表は `app/metrics/catalog.py` の 1 箇所のみ。

### (3) この環境の制約 (`docs/ArchitectureHandbook.md` §9)

| 制約 | 影響 |
| --- | --- |
| **`sadf` が無い** (導入もできない) | `sa` 経路は**フィクスチャによる単体テストのみ**。実出力での確認は不可。「実 `sadf` で確認した」と記録しない |
| **Docker が無い** | U008 の成果物はビルド・起動を確認できない。「ビルド確認済み」と記録しない |
| **開発 Python 3.14 / コンテナ 3.12** | **3.13 以降の構文・API を使わない。**この環境のテストでは検出できない |

* `sadf` が無いこと自体は**異常ではない**。`sar` のみで動作することが要求 (REQ-N-015)。`sa` は `unreadable` として一覧から除外され、直接指定時は 503 + `hint` を返す。

### (4) セキュリティ上、順序を変えてはならない実装 (ADR-007)

`fileId` の解決は **必ず** この順:
復号 → **正規表現 `^sar?[0-9]{2}$` で検証** → パス結合 → `realpath` 確認 → 存在確認。
正規表現検証をパス結合の後に回すと防御が成立しない。失敗はすべて 404 に丸める。

### (5) グラフの X 軸は線形軸 (ADR-006)

`type: 'linear'` + epoch ミリ秒 + `ticks.callback` で `HH:mm` 整形。
**カテゴリ軸を使わない** (点が等間隔に描かれ、欠測が視覚的に潰れる)。時間軸も使わない (追加依存が要る)。
