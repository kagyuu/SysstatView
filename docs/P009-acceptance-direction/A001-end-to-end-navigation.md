# 【テストID】A001 — 通し操作と状態復元 (観点C)

## 【目的】

* SC-01 で検索・ページ切り替え・行選択を行い、SC-02 でグラフを見て、戻ったときに**遷移前の状態が復元される**ことを確認する (REQ-F-014)。`require.txt` が明示的に求めた要求であり、本フェーズの最重要テストである。

## 【参照テスト計画】

* `docs/P006-test-plan.md` §2 観点C, §7
* `docs/P002-frontend-spec.md` §4.1 (シーケンス)

## 【対象モジュール】

* SC-01 / SC-02 / `SearchStateService` / `ApiService` / バックエンド全体

## 【前提条件】全モジュールビルドが成功していること

* U001〜U007 の単体テストが合格していること。
* バックエンドとフロントエンドが起動できること。

## 【使用するテストデータ】

* 実データディレクトリ (`sa` 9 件 + `sar` 9 件)。`sadf` 不在環境では `sar` 9 件が一覧に出る。

## 【事前準備】

* バックエンドを `SYSSTAT_LOG_DIR` = 実データディレクトリで起動する。
* フロントエンドをビルドし、同一オリジンで配信されている状態にする (開発サーバの proxy または nginx)。
* **一覧が 2 ページ以上になるよう `perPage` の既定 (10) に対して十分な件数があることを確認する。** `sar` のみ 9 件の環境では 1 ページに収まるため、`tmp_path` にコピーを作って 11 件以上に増やしたディレクトリを用いる。

## 【実行手順】

1. SC-01 を開く。開始日・終了日の初期値を記録する。
2. 期間を実データが含まれる範囲に設定して検索する。
3. **2 ページ目**へ移動する。
4. 先頭以外の行を選択する。
5. 「表示」を押して SC-02 へ遷移する。
6. SC-02 の表示内容を確認する。
7. 「戻る」を押して SC-01 へ戻る。
8. 復元された状態を確認する。

## 【実行コマンド】

* `npm --prefix frontend run e2e` (E2E ハーネスを用いる場合)
* E2E ハーネスが無い場合は、Angular のコンポーネントテストでルータを介した遷移を再現して検証してよい。その場合はその旨を記録する。

## 【期待結果】

* 手順1: 開始日 = 実行月の 1 日、終了日 = 実行月の末日。
* 手順3: ページリンクで 2 ページ目に移動でき、**2 ページ目の先頭行**が選択状態になる。
* 手順5: SC-02 へ遷移する。
* 手順6: 選択したファイル名・種別・採取日が表示される。各グラフの**前**に見出しと説明が表示される。グラフが 1 つ以上描画される。
* 手順8 (最重要): 次がすべて**遷移前と一致**する。
  * 開始日・終了日
  * 一覧の内容
  * **ページ番号が 2 のまま** (1 ページ目に戻らない)
  * **選択されていた行が選択されたまま** (先頭行に戻らない)
* 手順8: **`GET /api/log-files` が再実行されない** (`docs/P002-frontend-spec.md` §4.1)。ネットワークログまたは API 呼び出しのスパイで確認する。

## 【合否判定基準】

* 上記をすべて満たせば PASS。とくに手順8 の 4 項目のいずれかが復元されない場合は FAIL。
